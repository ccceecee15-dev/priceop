The workflow spine

The product is a sequence — Connect, Profile, Assess, Ask, Act. A demo feels like a screen tour precisely when there is no spine to walk along, so put it directly under the topbar on every workspace screen. Completion state should derive from the data, not be hard-coded. Pass the scope label outside .dr-flow — the spine scrolls horizontally and would clip it.

Truncation

Three components here carry explicit ellipsis rules: .dr-topbar__title, .dr-nav__item > span and .dr-usercard. Each sits in a fixed-height flex row and is allowed to shrink below its content width, so without them the text wraps and the fixed height clips it. Any new component with a hard height needs the same treatment — see readme.md, bug three.

Active must out-specify hover

.dr-pill:hover is specificity (0,2,0) and .dr-pill--active is (0,1,0), so hovering an active pill repainted its label copper-on-copper. Six explicit --active:hover rules exist for this — on pills, tabs, segments, nav items, nav sub-items and selected cards. A Tailwind port will likely reintroduce the bug, because Tailwind orders by utility rather than by state precedence.
